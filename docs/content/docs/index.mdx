---
title: email-utils
description: Small, focused packages for checking and normalizing email addresses.
---

`@email-utils` is four packages, each answering one question about an address.
Use the ones you need; each depends only on the packages before it.

| Package                         | Question                     | Answers with                              |
| ------------------------------- | ---------------------------- | ----------------------------------------- |
| `@email-utils/validator-syntax` | Is it well-formed?           | Parser, presets, TLD set                  |
| `@email-utils/classifier`       | What is it?                  | Provider registry, disposable, role, typo |
| `@email-utils/sanitizer`        | What is its canonical form?  | Provider-aware normalization              |
| `@email-utils/validator-dns`    | Can the domain receive mail? | MX, Null MX, signals                      |

validator-syntax, classifier, and sanitizer are synchronous and run in the
browser and in Node. validator-dns is async and runs on the server.

```ts ts2js
import { parseAddress } from '@email-utils/validator-syntax';

function domainOf(email: string): string | undefined {
  const result = parseAddress(email);
  return result.ok ? result.value.domain : undefined;
}
```

The [reference](/docs/reference/conventions) covers each package's options,
behavior, and [reason codes](/docs/reference/reason-codes), and the
[support matrix](/docs/reference/support-matrix) what each preset accepts and
each provider's rules. The [API reference](/docs/api/validator-syntax) covers
every export of the release candidates on npm's `next` tag.
